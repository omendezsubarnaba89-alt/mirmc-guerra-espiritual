# V12.1 · Recuperación desde expediente oficial

## Problema que resuelve

El progreso local permite offline y sincronización rápida, pero un navegador nuevo puede empezar vacío aunque Supabase ya tenga evidencia académica oficial.

V12.1 añade:

`official-recovery.html`

La herramienta compara:

- progreso de este dispositivo;
- `lesson_validations`;
- `exam_validations`.

## Regla de seguridad

La reconciliación es **solo ascendente**.

Puede:

- marcar localmente una lección que el servidor ya registra como aprobada;
- importar localmente un examen que el servidor ya registra como aprobado.

No puede:

- borrar progreso local;
- bajar puntuaciones;
- fabricar una aprobación que no exista en Supabase;
- crear o modificar certificados;
- alterar `lesson_validations` o `exam_validations`.

## Respaldo

Antes de cambiar el navegador, si `MIRMCSync.snapshot()` está disponible, guarda una copia bajo:

`mirmc-official-recovery-backup-v1`

Después intenta `MIRMCSync.push()` para que el snapshot local quede alineado con la evidencia oficial.

## Compatibilidad

El puente detecta de forma defensiva la operación de finalización expuesta por `MIRMCProgress` y usa `MIRMCAssessmentProgress.record()` únicamente cuando el examen está oficialmente aprobado y todavía no aparece aprobado localmente.

CI:

- `validate-official-recovery.yml`
- `validate-recovery-api.yml`

La segunda validación falla si la API de progreso cambia y deja de ser compatible con el puente.
