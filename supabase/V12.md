## Tablas académicas nuevas

### `lesson_validations`

Expediente oficial de las 15 lecciones.

El navegador autenticado puede leer únicamente sus propias filas mediante RLS. No tiene permisos directos de escritura.

### `exam_validations`

Mejor resultado oficial por usuario/nivel.

Mismo patrón de seguridad: lectura propia, escritura solo desde Edge Function.

### `exam_attempt_log`

Registro de intentos finales utilizado para el límite de 3 intentos oficiales por nivel en una ventana móvil de 24 horas.

### `academic_answer_keys`

Banco PRIVADO de claves de las evaluaciones finales.

- RLS habilitado.
- `anon` sin privilegios.
- `authenticated` sin privilegios.
- política deny explícita.
- lectura solo mediante `service_role` dentro de Edge Functions.

**Los datos de esta tabla no se versionan en GitHub.**

El archivo de migración crea el esquema, pero nunca debe contener las claves reales.

Si se reconstruye un entorno, las claves deben provisionarse mediante un mecanismo secreto/administrativo fuera del repositorio público y deben coincidir con el `version` de `assessment-data.js`.

### `certificates`

Registro verificable de finalización.

- una emisión por usuario;
- código aleatorio `MIRMC-GE-` + 16 hex;
- estado `active` / `revoked`;
- `academic_snapshot` privado;
- revocación no elimina el registro.

### `certificate_audit_log`

Auditoría `issue`, `revoke`, `reinstate`.

No accesible directamente desde el navegador.

## Edge Functions

### `academic-validation`

`verify_jwt = true`

Acciones:

- `status`
- `submit_lesson`
- `submit_exam`

Responsabilidades:

- validar sesión;
- aplicar secuencia de la Ruta;
- calificar mini evaluaciones;
- leer el banco privado de respuestas finales;
- comprobar versión del examen;
- aplicar rate limit;
- escribir expediente oficial.

### `certificate-management`

`verify_jwt = true`

Acciones:

- `mine`
- `eligibility`
- `issue`
- `admin_list`
- `revoke`
- `reinstate`

Un certificado solo puede emitirse usando `lesson_validations` + `exam_validations`, nunca `user_learning_state`.

### `admin-management`

V12 amplía el detalle administrativo con:

- progreso local/sincronizado;
- progreso oficial;
- exámenes oficiales;
- estado/código de certificado.

## Verificación pública

`public.verify_certificate(text)` es `SECURITY INVOKER`.

La función valida un código exacto y lo coloca en una configuración transaccional. La política RLS de `certificates` únicamente permite leer una fila cuyo código coincida con esa configuración.

Esto permite verificación exact-code sin permitir enumeración de certificados.

## Regla inquebrantable

Nunca añadir al repositorio:

- valores de `academic_answer_keys.answer_key`;
- `SUPABASE_SERVICE_ROLE_KEY`;
- claves `sb_secret_...`;
- contraseña de base de datos;
- secretos OAuth.

Los CI V12 fallan si detectan varias de estas regresiones.
